ENGINE ARCHITECTURE - FIRST SKETCH
STATUS: DRAFT v0.1 - for review (no technology decisions are final)

Data flow
---------
 [third-party sensors / loggers / SCADA / pump logs / schedules]
        |   (we build no hardware; see data_source_requirements.txt)
 CONNECTORS ------------------------------------------------------------
   vendor APIs, file drops, SCADA historians -> normalise units, clocks,
   metadata; tag each stream with its data tier (0 / 1 / 2)
        |
 INGEST ---------------------------------------------------------------
   time-series store (continuous / low-rate data)
   event store (raw high-rate windows, immutable)
   detection runs here on streams; the same detection library can be
   deployed on a partner gateway next to the sensor where allowed
        |
 CORE (event pipeline) ------------------------------------------------
   1. fusion: group arrivals across sensors (graph-based coincidence gate)
   2. classify (P2)            3. locate (P3, Bayesian on graph)
   4. quantify (P4, Joukowsky + twin)
   5. risk update (P5)         6. action plan + safety simulation (P6)
        |
 OUTPUTS --------------------------------------------------------------
   alerts (SMS/app/email) with location map and confidence
   operator console: event timeline, waveforms, map, pipe health
   optional: actuation interface to motorised/solenoid valves
             (human confirmation by default; auto-close only with
              simulated-safe closure profile)
        |
 LEARNING PLANE -------------------------------------------------------
   digital twin (parameters as distributions), data assimilation,
   training pipelines, model registry, shadow evaluation (05_)

  sim/         scenario generator for synthetic datasets

  docs/        this documentation

Technology questions to decide (see 08_research/open_questions.txt)
--------------------------------------------------------------------
  - Core numerics language: Rust vs C++ vs Julia vs JAX (differentiable);
    likely a compiled core + Python research layer.
  - Stores: time-series DB for summaries; object store for raw windows.
  - Stream processing: simple queue + workers first; heavier frameworks
    only if scale requires.
Principle: build the physics and signal cores as pure, deterministic,
heavily-tested libraries first. Services are thin shells around them.
