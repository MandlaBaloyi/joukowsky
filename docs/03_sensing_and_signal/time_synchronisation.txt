TIME SYNCHRONISATION: THE HIDDEN REQUIREMENT
STATUS: DRAFT v0.1 - for review

Principle
---------
Localisation from arrival times measures DIFFERENCES between clocks at
different sensors. The engine can only be as precise as those clocks agree.
    location error  dx = a * dt_clock / 2
With a ~ 1000 m/s, every 1 ms of clock disagreement moves the estimated
burst by ~0.5 m.

Options
-------
  Method                          Typical sync error    Verdict
  NTP over cellular               ~10-100 ms [VERIFY]   5-60 m error: NO
  Cellular network time           ms-level, variable    not reliable
  GNSS PPS disciplined clock      < 1 microsecond       YES (primary)
  PTP (IEEE 1588) on wired LAN    sub-microsecond       YES where wired
  Post-hoc alignment from a
  common known event              ~ sample period       YES (calibration)

What we require from data sources (we build no hardware)
--------------------------------------------------------
1. Tier 2 sources should timestamp each SAMPLE from a GNSS-disciplined
   (or PTP) clock, as commercial transient loggers do.
2. Each source states its time source and expected accuracy; when a
   device loses its time reference it should say so. The location
   algorithm uses that uncertainty (P3).
What the engine does in software
--------------------------------
3. Self-check: events seen by several sensors with a known source (e.g.
   scheduled pump start at a known location) give travel-time residuals;
   a persistent offset at one node indicates a clock problem, which the
   engine estimates and corrects (05_learning_systems). This lets the
   engine partly repair poorly synchronised sources in software.
4. Record, never discard, raw timestamps and clock-quality metadata.

Single-sensor alternative
-------------------------
Where two synchronised sensors are not available, the time between the
direct arrival and reflections from known features (dead end, reservoir,
closed valve) can bound location using ONE sensor's clock only. Less
robust in branched networks; kept as a fallback method (04_).

IMPLEMENTATION NOTE (2026-09-28, crates/domain/localisation/src/clocks)
Measured (study V-S1 part 2, tests/localisation/simulation/clock_study):
two sensors, burst 700 m from S1, clocks off by sigma_c each, 100 trials:
    GNSS          0.1 ms  ->  0.14 m RMS   (theory a sigma_c/sqrt2: 0.13 m)
    good NTP      1 ms    ->  0.68 m       (0.72 m)
    NTP cellular  10 ms   ->  7.3 m        (7.1 m)
    poor NTP      50 ms   ->  36.8 m       (35.4 m)
with the 90% region still holding the truth 90-100% of the time when the
clock uncertainty is declared. Item 3 above (software self-check) is
implemented as least-squares clock-offset estimation from events with
KNOWN sources, relative to one reference sensor: offsets recovered to
~0.16 ms from three hydrant operations; a burst mislocated by 21 m with
unrepaired NTP clocks is found again within 0.1 m after repair. A sensor
that never shares an event with the others is refused, never guessed.
