SIGNAL PROCESSING AND DETECTION
STATUS: DRAFT v0.1 - for review

Context: 04_detection_and_localisation/event_detection.txt defines a
layered detector (pre-processing, baseline, change detection, onset
refinement, network fusion). This file says what each layer is built with.

The finding: there is no mature Rust library for transient detection in
pipes. The mathematics is well published; the implementation is ours.

1. Building blocks
------------------------------------------------------------------------
Filters (anti-alias, decimation, baseline)                      [BUILD]
  FIR/IIR design and application, robust medians, exponential smoothing,
  small Kalman filters. Small, testable, deterministic; written in the
  signal crate. The same code must compile for edge gateways (P6), so
  it avoids heap allocation in the per-sample path.

Change detection
  CUSUM (two-sided, Page 1954)                                  [BUILD]
    First-pass detector; cheapest; edge-friendly.
  GLR step test over a sliding window                           [BUILD]
  Multi-scale wavelet detail energy (Haar / Daubechies)         [BUILD]
    Small discrete wavelet transform of our own; no dependency needed.
  Bayesian online change-point (Adams & MacKay 2007)
    changepoint crate (Redpoll)                                [ASSESS]
    bocpd crate (log-space, bounded memory)                    [ASSESS]
    Likely outcome: our own implementation, because we need a
    predictive model specific to pressure residuals (heavy-tailed,
    autocorrelated) and bounded, allocation-free edge execution. The
    crates are useful as test oracles.

Onset (arrival-time) picking                                    [BUILD]
  AIC picker (from seismology), piecewise-linear onset fit, sub-sample
  refinement. Output: onset time + uncertainty sigma_t. This number
  drives localisation accuracy (dx = a * dt / 2), so it gets the
  heaviest testing: synthetic fronts with known onset, varying noise,
  rise time and sample rate (study V-S1).

Modal / oscillation analysis                                    [BUILD]
  Prony and matrix-pencil methods on faer SVD; gives dominant periods
  (4L/a signatures) and damping ratios - key classification features.

Spectral tools                                                  [TRIAL]
  rustfft / realfft for spectra and frequency-response functions.

STATUS 2026-09-28: first detector built (crates/domain/detection, jk-detection,
no dependencies):
  - noise: robust sigma from first differences (MAD), drift-proof;
  - baseline: Brown's double exponential smoothing (level AND slope), so
    demand drift leaves no lag - a plain moving average failed the drift
    test by design (lag = slope x time constant looked like an event);
  - CUSUM (two-sided, allocation-free per sample, edge-ready);
  - onset: STEP-AREA method - exact for integrating loggers at any clock
    phase; half-level interpolation would be biased up to ~9% of a sample.
Validated (tests/detection): delay = floor(h/(d-k)) + 1 exactly; zero false
alarms in 24 h of Gaussian noise (11 M samples) and in +/-3 m drift; noisy
timing RMS 0.012 sample with honest uncertainty (99.8% inside 2 sigma);
V-S1 end to end (simulated burst -> 128 S/s loggers, random phase, 2 cm
noise -> detect -> locate): 0.04 m location error, 0.07% sizing error.
CAVEATS: Gaussian noise, sharp simulated fronts and perfect clocks are the
best case; real noise has heavier tails and plastic pipes smear fronts
(viscoelasticity, S6) - rung 4 data must re-measure all of this.
OPEN: in the V-S1 sweep, 1000 S/s with 0.5 cm noise gave 0.077 m, worse
than 128 S/s. Hypothesis (unproven): the 1 ms simulation step limits the
truth at that rate. To test: rerun with a 0.1 ms simulation.
Not yet: GLR, wavelet and Bayesian online change-point detectors
(benchmarks by ROC curve), clock-error part of V-S1, heavy-tailed noise.

2. Edge portability
------------------------------------------------------------------------
The detection library is split: a no_std-compatible core (per-sample
math, fixed-size buffers) and a std layer (I/O, logging). That keeps the
door open to partner gateways and microcontrollers without a rewrite.
[VERIFY which partner gateway platforms exist: ARM Linux is assumed.]
